# 2026-09-09 앱·웹 첫 진입 흐름 QA

## 결론

자동화 및 정적 검증은 **PASS**다. 실제 iPhone/Android 상호작용 검증은 남아 있다.

첫 진입 정책은 다음과 같이 확정했다.

| 사용자 상태 | 네이티브 앱 | 웹 |
| --- | --- | --- |
| 세션 확인 중 | 짧은 세션 복구 화면 | 공개 랜딩 또는 `/auth` 로딩 화면 |
| 로그아웃 | 로그인·회원가입 | `/` 공개 랜딩, CTA에서 `/auth` 이동 |
| 신규 로그인 완료 | 3단계 제품 온보딩 | 기존 인증 후 온보딩 흐름 유지 |
| 온보딩 완료한 재방문 | 앱 본 화면 | 요청한 서비스 화면 |
| 비밀번호 복구 | 인증/복구 화면 우선 | 인증/복구 화면 우선 |

네이티브의 소개 화면은 검색 유입용 랜딩이 아니라 로그인한 신규 사용자에게 기능을 설명하는 **온보딩**이다. 웹의 `/`만 공개 랜딩과 SEO 획득 역할을 가진다.

## 구현 및 수정

- 진입 분기를 순수 함수 `resolveMobileEntryScreen`으로 분리해 `loading → auth → onboarding → app` 우선순위를 테스트 가능하게 만들었다.
- 온보딩에 현재 단계, 건너뛰기, 명시적인 접근성 레이블을 추가했다.
- 작은 화면과 큰 글자에서도 하단 동작이 잘리지 않도록 전체 화면을 스크롤 가능하게 하고 버튼 폭을 유연하게 만들었다.
- 원격 소개 이미지가 늦거나 실패해도 빈 화면 대신 즉시 로컬 아이콘 fallback을 표시한다.
- 웹 루트가 공개 랜딩을 유지한다는 계약 테스트를 추가했다.

## QA에서 발견해 수정한 이슈

| 우선순위 | 증상 | 처리 |
| --- | --- | --- |
| P2 | 폭이 좁은 기기에서 `이전`과 `다음` 버튼의 고정 폭 합계가 콘텐츠 폭을 넘을 수 있음 | 다음 버튼을 가변 폭으로 변경하고 화면을 스크롤 가능하게 처리 |
| P2 | 원격 일러스트 로딩이 느리면 온보딩 상단이 잠시 비어 보일 수 있음 | 로딩·실패 중 아이콘 fallback 표시 |
| P1 | Apple 유료 설정을 미뤄도 iOS 버튼과 entitlement가 기본 활성화되어 로그인 실패 또는 Personal Team 빌드 실패 가능 | 구현은 유지하고 `EXPO_PUBLIC_ENABLE_APPLE_AUTH` 기본값을 `false`로 둬 버튼·plugin·entitlement를 함께 비활성화 |

수정 후 남은 P0/P1 이슈는 자동화·정적 범위에서 발견되지 않았다.

- 진입 흐름·접근성 집중 테스트: 10/10

`skill-creator`의 `quick_validate.py`는 로컬 Python에 `PyYAML`이 없어 실행되지 않았다. 저장소 의존성을 추가하지 않고 Ruby 기본 YAML 파서로 동등한 구조 검사를 수행했다.

## 실기기에서 남은 검증

1. 앱 데이터 삭제 또는 신규 계정으로 실행해 로그인 화면이 먼저 보이는지 확인한다.
2. 신규 가입 후 온보딩 1/3부터 시작하며 다음·이전·점 이동이 모두 되는지 확인한다.
3. `건너뛰기`와 마지막 `시작하기`가 각각 본 화면으로 이동하고, 앱 재시작 뒤 온보딩이 반복되지 않는지 확인한다.
4. iPhone SE급 폭, Android 소형 화면, 큰 글자 설정에서 버튼과 본문이 잘리지 않는지 확인한다.
5. 네트워크가 느리거나 끊긴 상태에서 소개 이미지 fallback과 온보딩 완료 실패 메시지가 보이는지 확인한다.
6. 기존 온보딩 완료 계정은 로그인·세션 복구 뒤 본 화면으로 바로 이동하는지 확인한다.
